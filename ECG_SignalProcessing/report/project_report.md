# ECG Signal Processing and Analysis Using MATLAB

## Abstract
This project implements a MATLAB workflow for conditioning a single ECG lead, inspecting its spectrum, detecting QRS peaks, estimating heart rate, and optionally comparing detections with annotations. The code separates filtering, FFT calculation, detector stages, and performance metrics. Numerical results depend on the recording supplied at run time.

## Introduction and problem statement
Ambulatory ECGs contain diagnostically relevant cardiac morphology mixed with baseline motion, mains coupling, muscle activity, and instrument noise. A sound engineering workflow must reduce interference while preserving beat morphology, expose algorithm stages, and quantify limits rather than report unsupported accuracy.

## Objectives
Load one channel with its sampling rate; inspect time and frequency domains; apply baseline, notch, and low-pass filters; detect R peaks using a Pan-Tompkins-inspired chain; calculate RR/heart rate; compare detections with optional annotations; save figures and quality descriptors.

## ECG and dataset
The recommended data source is the PhysioNet MIT-BIH Arrhythmia Database. It consists of 48 two-channel, approximately half-hour ambulatory excerpts digitized at 360 samples/s, with expert beat annotations. See `../data/README.md` for acquisition and export instructions. The included loader consumes exported CSV or MAT, not native WFDB encoding.

## Acquisition, noise, and preprocessing
ECG electrodes and front-end amplifiers measure lead voltage; ADC sampling creates x[n]. Baseline wander is addressed with a fourth-order 0.5 Hz Butterworth high-pass. A second-order notch targets configurable 50/60 Hz mains with Q=35. A fourth-order 40 Hz Butterworth low-pass attenuates high-frequency noise. Offline forward-backward filtering avoids phase delay but is noncausal, doubles effective order, and can create endpoint transients. Cutoffs must be changed for tasks emphasizing ST segments or other morphology.

## Filter analysis and FFT
MATLAB returns filter coefficients; `freqz` visualizes each response. `computeFFT` explicitly calls `fft`, normalizes a single-sided spectrum, and reports positive frequencies. Resolution is fs/NFFT; zero padding improves plot interpolation only. Raw spectrum can reveal low-frequency drift, mains peaks, and broad high-frequency energy, but does not alone prove a noise source. No PSD estimate is produced in this baseline.

## R-peak and heart-rate methods
The detector applies 5–20 Hz band-pass, first difference, squaring, 150 ms moving integration, a global fraction-of-maximum threshold, a 250 ms refractory rule, and local waveform maximum refinement. Its stages are exposed for inspection. The threshold is not the full adaptive Pan-Tompkins logic and requires validation, especially with amplitude changes, ectopy, and noise. RR and bpm follow the equations in `../MATHEMATICS.md`.

## Performance evaluation and signal quality
If aligned reference sample indices are supplied, detections are greedily matched one-to-one within 150 ms and TP/FP/FN, sensitivity, precision, and F1 are saved. A single detection can match only one annotation. Window cropping requires annotation indices to be shifted to the cropped signal's coordinate system. Raw/processed RMS, mean, spread, range, baseline proxy, and residual proxy are reported. SNR is not reported because a true clean reference is absent.

## Results, discussion, and limitations
Figures and tables are generated by running `main.m` on a recording. This package does not include measured performance scores. Current limitations include CSV/MAT input only, a global detection threshold, no beat classification, no clean reference for SNR, and a short default analysis window. Results also depend on lead selection, units, sampling frequency, mains frequency, and annotation alignment.

## Future work and conclusion
Add direct WFDB parsing/import, adaptive signal/noise threshold tracking, explicit PSD/window analysis, robust multi-record patient-independent evaluation, filter alternatives and cutoff/order sweeps, and a documented causal streaming variant. This project provides a transparent MATLAB foundation, not clinical decision support.
